로봇을 만들다 보면 같은 알고리즘을 **3주 뒤에 다시 검색하고 있다.** 그때마다
"이게 정확히 뭘 푸는 거였지"부터 되짚는 게 아까워서, 실제로 쓰이는 것들을 섹터로 잘라 사전으로 만들었다.

각 항목의 설명은 정의가 아니라 **"이게 없으면 뭐가 안 되는가"** 다. 알고리즘은 답이 아니라
누군가 겪은 문제의 해결책이고, 문제를 모르면 언제 써야 할지도 모르기 때문이다.

> **이 페이지는 색인이다.** 항목별 상세(동작 원리 · 원전 논문 · 구현 코드 · 내가 쓰면서 겪은 것)는
> 하나씩 글로 풀어 이 아래에 붙여 나간다. 아직 링크가 없는 항목은 안 쓴 것이다.

**도메인 표기** — `AV` 자율주행차량 · `AGV` 산업 무인운반차/AMR · `MR` 다중로봇·플릿

현재 **10개 섹터 · 119개 항목**.


## S0. 센서 · 전처리

| 이름 | 유형 | 푸는 문제 | 도메인 |
|---|:---:|---|:---:|
| 카메라 캘리브레이션 (Zhang) | 알고리즘 | 렌즈는 완벽한 핀홀이 아니라 왜곡이 있고 초점거리도 카메라마다 다르다. 이걸 미리 구해두지 않으면 "화면의 이 픽셀이 실제로 몇 미터 앞이다"라는 환산 자체가 성립하지 않는다 | AV AGV |
| IPM 역투시 변환 | 수학모델 | 카메라로 도로를 찍으면 원근법 때문에 먼 차선일수록 화면에서 좁아 보여 실제 곡률을 계산할 수 없다. 위에서 내려다본 것처럼 이미지를 펴준다 | AV |
| DLT (Direct Linear Transform) | 알고리즘 | 천장에 달린 카메라가 찍은 픽셀 좌표를 바닥 위 로봇의 실제 (x, y) 좌표로 바꾸는 계산 | AGV MR |
| 스캔 deskew (모션 보상) | 알고리즘 | 라이다가 한 바퀴 스캔하는 동안 로봇이 움직이면 스캔 앞부분과 뒷부분이 서로 다른 위치 기준으로 찍혀 점군이 휘어져 보인다. 이 왜곡을 로봇 움직임만큼 보정한다 | AV AGV |
| RANSAC 평면 적합 · Patchwork++ | 알고리즘 | 라이다 점군에서 바닥을 장애물로 잘못 인식하면 로봇이 아무 데도 못 간다고 판단해버린다. 노이즈 섞인 점들 속에서 바닥에 해당하는 평면만 골라낸다 | AV |
| Voxel grid 다운샘플 | 알고리즘 | 라이다 점군은 한 프레임에 수십만 점이 나와 다 처리하면 실시간이 안 된다. 공간을 작은 격자로 나눠 격자당 대표점 하나만 남긴다 | AV |
| ApproximateTime 동기화 | 알고리즘 | 서로 다른 센서를 융합하려면 같은 순간의 데이터끼리 맞춰야 하는데, 타임스탬프가 안 맞으면 오히려 잘못된 정보를 합쳐 성능이 나빠진다 | AV AGV |
| HSV 임계 분할 | 알고리즘 | RGB 값으로 임계값을 정해두면 조명이 바뀌는 순간(그늘·역광) 다 틀어진다. 색상·채도·명도를 분리한 HSV로 조명 변화에 더 강하게 잡는다 | AV |

## S4. 전역 경로계획 (Global Planning)

| 이름 | 유형 | 푸는 문제 | 도메인 |
|---|:---:|---|:---:|
| Dijkstra | 알고리즘 | 그래프에서 "여기서 저기까지 가장 짧은 길"을 최적성 보장하며 찾는다. 목적지 방향은 고려 안 해서 사방으로 다 뒤진다 | 전부 |
| **A\*** | 알고리즘 | Dijkstra는 목적지 방향을 몰라 사방을 똑같이 탐색해 낭비가 크다. A\*는 목적지까지 대략 남은 거리를 추정해 그 방향 위주로 탐색을 좁힌다 | 전부 |
| Weighted A\* / Theta\* | 알고리즘 | A\*를 격자 위에서 돌리면 이동 방향이 8방향으로 제한돼, 실제로는 직선으로 가도 되는 길을 계단식 지그재그로 만든다. 이를 완화한다 | AGV |
| Jump Point Search | 알고리즘 | 균일한 격자에서 A\*가 값이 똑같은 인접 칸들을 하나하나 다 펼쳐보느라 느리다. 뻔한 구간은 건너뛰어 속도를 올린다 | AGV |
| D\* / D\* Lite | 알고리즘 | 처음 계획한 경로에 없던 장애물이 나타나면 A\*는 처음부터 다시 계산해야 한다. D\*는 바뀐 부분만 다시 계산해 재계획을 빠르게 한다 | AV AGV |
| **Hybrid A\*** | 알고리즘 | 격자 위 A\*는 로봇이 어느 칸으로든 순간이동할 수 있다고 가정하지만, 차량은 제자리 회전이 안 된다. 실제로 움직일 수 있는 궤적만 후보로 삼는다 | AV AGV |
| Reeds-Shepp / Dubins 최단곡선 | 알고리즘 | 최소 회전반경이 있는 차량이 A에서 B(방향 포함)로 가는 가장 짧은 곡선을, 탐색 없이 공식으로 바로 구한다 | AV AGV |
| State lattice | 알고리즘 | 아무 곡선이나 이어붙이면 로봇이 실제로 따라갈 수 없는 궤적이 나올 수 있다. 미리 실행 가능한 궤적 조각만 라이브러리로 만들어 이어붙인다 | AV |
| RRT / RRT-Connect | 알고리즘 | 탐색해야 할 공간의 차원이 매우 높으면 격자로 다 훑는 방식은 계산량이 폭발한다. 무작위로 점을 뿌려 트리를 뻗어 빠르게 되는 길 하나를 찾는다 | MR |
| RRT\* / Informed RRT\* / BIT\* | 알고리즘 | RRT는 빠르지만 처음 찾은 경로가 최적(가장 짧음)이라는 보장이 없다. 계속 개선해 최적해에 점점 가까워지게 한다 | MR |
| PRM | 알고리즘 | 같은 지도에서 여러 번 계획할 거라면 매번 새로 탐색하지 말고, 갈 수 있는 길들의 로드맵을 미리 한 번 깔아두고 이후엔 그 위에서 빠르게 찾는다 | AGV |
| NavFn / Smac Planner (Nav2) | 구현체 | 위의 이론들을 실제 로봇 미들웨어(ROS 2 Nav2)에서 바로 쓸 수 있게 구현한 것 | AGV |
| 경유점 라우팅 (waypoint following) | 패턴 | 최단경로가 아니라 정해준 순서·경로대로 가야 하는 운영상 요구(창고 통로 등)를 처리한다 | AGV MR |


## S5. 지역 계획 · 궤적 (Local Planning & Trajectory)

| 이름 | 유형 | 푸는 문제 | 도메인 |
|---|:---:|---|:---:|
| **DWA / DWB** | 알고리즘 | 전역 계획이 그린 경로는 지금 로봇이 실제로 낼 수 있는 속도·가속도를 모른다. 현재 동역학 한계 안에서 낼 수 있는 속도 후보만 놓고 다음 한 스텝을 고른다 | AGV |
| TEB (Timed Elastic Band) | 알고리즘 | 경로를 공간뿐 아니라 시간 축까지 포함해서, 고무줄처럼 장애물에 밀리며 변형시켜 최적화한다 | AGV |
| **MPPI** | 알고리즘 | 충돌 여부처럼 됨/안됨으로 딱 갈리는 비용함수는 미분이 안 돼 고전적인 MPC로는 못 푼다. 여러 궤적을 무작위로 샘플링해 평균내는 방식으로 우회한다 | AGV AV |
| **MPC / NMPC** | 알고리즘 | 속도·조향 한계, 충돌 회피 같은 제약을 지키면서 앞으로 N스텝 동안의 미래를 한꺼번에 최적화한다 | AV AGV |
| Frenet 궤적 생성 (Werling) | 알고리즘 | 곡선 도로에서는 xy 좌표보다 "차선을 따라 얼마나 갔는지(s)"와 "차선에서 옆으로 얼마나 벗어났는지(d)"로 표현하는 게 훨씬 쉽다 | AV |
| 다항식 궤적 (quintic · jerk-optimal) | 알고리즘 | 승차감을 결정하는 건 가속도가 아니라 가속도의 변화율(저크)이다. 저크까지 부드러운 다항식으로 궤적을 만든다 | AV |
| VO / RVO / **ORCA** | 알고리즘 | 여러 이동체가 서로를 피하려고 각자 회피 동작을 하면 상대의 회피를 예측 못 해 진동하듯 왔다갔다 할 수 있다. 이를 막는 상호 회피 알고리즘 | MR |
| Potential field (APF) | 알고리즘 | 목표는 끌어당기고 장애물은 밀어내는 힘의 합으로 즉시 다음 동작을 정한다. 계산이 가볍지만 힘이 상쇄되는 지점(지역 최소)에 갇힐 수 있다 | MR |
| Elastic Band | 알고리즘 | 전역 경로 자체를 장애물이 밀어내는 고무줄처럼 다뤄서 실시간으로 변형한다 | AGV |
| S-T graph / 속도 프로파일 | 표현 | 어느 경로로 갈지와 그 경로를 언제 어떤 속도로 지나갈지는 별개의 문제라서 따로 계산한다 | AV |
| Bezier / Clothoid / Spline 평활 | 수학모델 | 꺾인 점들을 그대로 이어 만든 경로를 로봇이 따라가면 조향이 급격히 튄다. 부드러운 곡선으로 다듬는다 | AV AGV |
| 가상 장애물 주입 | 패턴 | 실제로는 장애물이 없어도, 소프트웨어적으로 "여기는 못 간다"는 제약을 인위적으로 만들어야 할 때가 있다 | AGV MR |


## S6. 제어 · 경로추종 (Control)

| 이름 | 유형 | 푸는 문제 | 도메인 |
|---|:---:|---|:---:|
| PID | 알고리즘 | 목표와 현재의 차이(오차)를 보고 그걸 얼마만큼의 모터 명령으로 바꿀지 정하는 가장 기본적인 피드백 제어 | 전부 |
| **Pure Pursuit** | 알고리즘 | 경로 전체를 보지 않고 전방의 한 점만 보고 거기로 향하도록 조향각을 기하학적으로(원 그리기) 계산한다 | AV AGV |
| **Regulated Pure Pursuit (RPP)** | 알고리즘 | Pure Pursuit은 커브가 급하거나 장애물이 가까워도 속도를 안 줄인다. 그런 상황에 맞춰 속도를 조절하도록 보강한다 | AGV |
| Stanley controller | 알고리즘 | 앞바퀴 기준으로 경로에서 옆으로 벗어난 정도(횡오차)와 방향이 틀어진 정도(헤딩오차)를 한 수식에 같이 넣어 조향을 계산한다 | AV |
| Kinematic bicycle model | 수학모델 | 4륜 차량을 앞뒤 좌우 바퀴 각각으로 계산하면 식이 복잡해서, 앞뒤 각 축을 바퀴 하나로 뭉쳐 자전거처럼 단순화한다 | AV |
| 차동구동 역기구학 | 수학모델 | "앞으로 이 속도로, 이만큼 회전하며 가라(v, ω)"는 명령을 실제 좌우 바퀴 각각의 회전 속도로 바꾸는 계산 | AGV MR |
| Mecanum / 옴니 역기구학 | 수학모델 | 차동구동과 달리 옆으로도 움직일 수 있는 바퀴 구조라 역기구학 식 자체가 다르다 | AGV |
| LQR / iLQR·DDP | 알고리즘 | PID처럼 감으로 게인을 튜닝하지 않고, 비용(오차+에너지 등)을 최소화하는 제어값을 수학적으로 유도한다 | AV |
| 비전 서보 (visual servoing) | 알고리즘 | 목표 위치가 지도 좌표가 아니라 카메라 화면에 보이는 물체일 때, 그 이미지 정보를 직접 이용해 제어한다 | AGV |
| 최종 정렬 / RotationShim | 구현체 | 목적지 좌표엔 도착했는데 방향이 틀어져 있으면 도킹·적재가 안 되므로, 마지막에 방향을 맞추는 별도 단계 | AGV |
| S-curve 가감속 | 알고리즘 | 속도를 사다리꼴로 바꾸면 가속도의 변화율(저크)이 순간적으로 무한대가 돼 기계에 충격을 준다. 부드러운 S자 곡선으로 저크를 유한하게 만든다 | AGV |


## S7. 다중로봇 · 플릿 (Multi-Robot & Fleet)

| 이름 | 유형 | 푸는 문제 | 도메인 |
|---|:---:|---|:---:|
| **CBS / ECBS** | 알고리즘 | 로봇 여러 대의 경로를 각자 따로 계획하면 서로 충돌하는 경로가 나올 수밖에 없다. 충돌을 찾아 순차적으로 제약을 더해가며 다 함께 풀어낸다 | MR AGV |

| **경매 / 시장기반 배차 (CBBA)** | 알고리즘 | 작업량이 많아지면 중앙 하나가 누구에게 어떤 일을 줄지 전부 계산하기 어렵다. 로봇들이 서로 입찰하듯 작업을 나눠 갖는다 | MR |
| 헝가리안 알고리즘 | 알고리즘 | N개의 작업과 M대의 로봇을 1:1로 최적 매칭하는 걸 다항시간 안에 정확히 풀어낸다 | MR |
| Leader-follower 편대 | 알고리즘 | 여러 로봇이 대열·대형을 유지하며 함께 이동해야 하는 문제 | MR |
| Consensus / Flocking (Reynolds) | 알고리즘 | 중앙 관제 없이 각자 이웃의 정보만으로 새떼·물고기떼 같은 집단 행동을 만들어낸다 | MR |
| 커버리지 (BCD · Spanning Tree) | 알고리즘 | 한 지점에 가는 게 아니라 청소 로봇처럼 영역 전체를 빠짐없이 훑어야 하는 문제 | MR AGV |
| **Heartbeat / liveness 판정** | 패턴 | 이미 죽은 로봇을 살아있다고 믿고 계속 일을 배정하면, 그 작업들이 영영 처리되지 않는 블랙홀이 된다 | MR |
| 도메인 격리 / 2-Context 브리지 | 패턴 | 로봇이 많아지면 통신 미들웨어(DDS)의 자동 탐색 트래픽 자체가 네트워크를 마비시킬 수 있어 통신 영역을 분리한다 | MR |
| Stale data 보정 | 패턴 | 네트워크 지연으로 늦게 도착한 다른 로봇의 옛 상태 정보를 마치 현재 상태인 것처럼 착각해서 판단하면 안 된다 | MR |
| **VDA 5050 / OpenRMF** | 규격 | 서로 다른 제조사의 AGV들을 하나의 관제 시스템으로 묶기 위한 공통 표준 인터페이스 | AGV MR |
