WaSaB Robot Agent Process Map

현재 코드 기준: wasab_robot_agent.agent_node가 로봇 로컬 ROS 도메인과 콘솔 공유 도메인을 2-Context로 연결한다. agent pose는 /amcl_pose 기반으로 경량화했고, 도킹 detector는 Nav2 접근이 끝난 뒤 SEARCH_TAG에서만 기동한다.

robot_ctx / 로봇 로컬 도메인 console_ctx / 콘솔 공유 도메인 agent가 띄우는 서브프로세스 외부 상시 Nav2/bringup 스택 해결된 CPU 고갈 / 남은 검증 지점

0. agent가 필요한 이유

핵심 이유는 로봇 내부 ROS graph를 콘솔에 직접 노출하지 않고, 로봇별 경계면을 하나 두어 ROS_DOMAIN_ID 분리, 다중 로봇 이름 충돌, 운영 정책을 한 곳에서 흡수하기 위해서다. 현재 구현은 표준 domain_bridge 패키지가 아니라 agent 내부의 2-Context 수동 브리지다.
도메인 분리 로봇은 자기 로컬 ROS_DOMAIN_ID에서 Nav2, AMCL, bringup을 유지하고, 콘솔은 공유 WASAB_CONSOLE_DOMAIN에서 fleet 상태와 명령만 다룬다.
로봇별 이름 경계 로봇 내부 전역 토픽 /cmd_vel, /initialpose를 콘솔 쪽 /robot_<id>/cmd_vel, /robot_<id>/set_initialpose로 분리한다.
콘솔 단순화 AdminGUI는 로봇 내부 launch, detector, relocalizer, Nav2 세부 토픽을 직접 알지 않고 명령 발행과 이벤트 구독만 담당한다.
운영 정책 게이트 재측위 detector가 켜진 상태의 도킹 거부, 명령 watchdog, timeout 정리 같은 정책을 UI가 아니라 로봇 가까운 agent에서 일관되게 처리한다.
네트워크 장애 격리 콘솔 DDS 연결이 흔들려도 로봇 로컬 Nav2와 정밀주차 FSM은 로봇 안에서 계속 실행되고, agent가 상태와 결과를 다시 올리는 완충층이 된다.
가벼운 gateway 원칙 agent는 실시간 제어기가 아니라 저주파 상태 요약과 명령 relay를 맡는다. 고주파 /tf 소비는 제거하고 /amcl_pose 기반으로 경량화했다.

0-1. agent가 하는 일

agent는 로봇 안에 상주하는 현장 매니저다. 콘솔 버튼과 명령을 실제 로봇 동작으로 바꾸고, 필요한 무거운 프로세스를 켜고 끄며, 결과와 상태를 다시 콘솔로 올려준다.
콘솔 명령 전달 수동 조종, 초기 위치 설정, 모드 변경, 재측위, 도킹 명령을 받아 로봇 로컬 ROS 토픽으로 안전하게 전달한다.
재측위 실행 재측위 버튼을 받으면 AprilTag detector와 relocalizer를 켜고, 성공 또는 timeout 후 detector를 종료해 CPU를 회수한다.
도킹 실행 목표 태그 위치를 읽고 approach pose를 계산한 뒤, 필요하면 Nav2 접근 주행을 실행하고 정밀 주차 단계로 넘긴다.
프로세스 생명주기 관리 재측위 launch와 도킹 launch를 on-demand로 실행하고, 완료·실패·stop·timeout·agent 종료 시 관련 process group을 정리한다.
상태 보고 heartbeat, 배터리, 모드, 위치, 태그 관측, 재측위 결과, 도킹 결과를 콘솔 공유 도메인으로 발행한다.
충돌 방지와 CPU 절감 재측위 detector가 켜져 있으면 도킹을 거부해 카메라 충돌을 막고, pose 소스를 /tf에서 /amcl_pose로 바꿔 CPU를 낮춘다.

  • 2Hz heartbeat/event drain timer

RobotAgent 프로세스

python3 -m wasab_robot_agent.agent_node scripts/start_agent.sh가 기동. entry point는 agent.
  • 프로세스 내부에 ROS context 2개 생성
  • _to_robot queue로 cross-context 명령 전달
  • 서브프로세스 process group 관리
  • 로그: ~/agent.log, dock/relocalize 별도 로그
wasab_agent_robot_<id> robot_ctx. 로봇 로컬 ROS_DOMAIN_ID에서 실제 로컬 토픽 발행.
  • 20Hz drain/watchdog timer
  • /amcl_pose subscription으로 heartbeat pose 갱신
  • /initialpose 수신 시 pose 즉시 반영
  • POSE_STALE_S=5.0: 오래된 pose면 dock nav 판정에서 Nav2 사용
  • /cmd_vel, /initialpose, /wasab/cmd_mode publish
  • /wasab/tag_observation, /battery/voltage, /wasab/docking_state subscribe

On-demand 서브프로세스

relocalization.launch.py 콘솔 재측위 시작 요청 시 agent가 실행.
  • apriltag_detector
  • apriltag_relocalizer
  • timeout: 30s
  • 로그: ~/agent_detector.log
dock.launch.py 콘솔 도킹 시작 요청 시 agent가 실행.
  • precision_parking 단일 Node launch
  • Nav2 접근 중 detector 프로세스 없음
  • SEARCH_TAG 진입 시 precision_parking이 apriltag_detector spawn
  • DONE/FAILED/stop/shutdown 시 detector 회수
  • timeout: 90s
  • 로그: ~/agent_dock.log

4. agent가 관리하는 ROS 토픽

방향 토픽 역할 비고
Console -> Agent /robot_<id>/cmd_vel 선택 로봇 수동 속도 명령 robot_ctx가 /cmd_vel로 재발행. 0.3s watchdog.
Console -> Agent /robot_<id>/set_initialpose 초기 위치 지정 robot_ctx가 /initialpose로 복사 발행.
Console -> Agent /robot_<id>/relocalize_cmd detector start/stop, calibrate, rearm detector start는 agent가 로컬 launch 실행.
Console -> Agent /robot_<id>/dock_cmd 도킹 start/stop agent가 approach pose 계산 후 dock launch 실행. 재측위 detector 활성 중이면 즉시 거부.
Robot -> Console /robots/heartbeat id, ip, mode, battery, pose 2Hz, best effort.
Robot -> Console /robots/tag_status 최근 tag observation 요약 /wasab/tag_observation snapshot 기반.
Robot -> Console /robots/dock_event started, done, failed, cancelled, timeout /wasab/docking_state terminal 상태 기반.

  • /navigate_to_pose action server
  • cmd_vel_nav -> velocity_smoother -> /cmd_vel

6. 이슈 / 원인분석 / 해결조치

이슈 원인분석 해결조치 / 결과
콘솔 도킹(agent ON) 시 Nav2 주행 중 멈춤 또는 nav_failed. py-spy 결과 agent CPU의 약 85%가 rclpy executor wait-set 재구성. TransformListener가 /tf 35~55Hz로 robot_ctx를 계속 깨웠다. TF 연산 자체는 거의 0%. agent pose 소스를 TF polling에서 /amcl_pose 이벤트로 변경. TransformListener와 5Hz pose timer 제거. robot_ctx CPU 약 30% → 약 8%.
Nav2 접근 중 detector와 CPU/카메라 경합 가능성. 기존 도킹 launch는 detector와 precision_parking을 co-launch했다. Nav2 주행 중 detector 부하를 분리할 필요가 있었다. dock.launch.py에서 detector 제거. precision_parking이 SEARCH_TAG에서만 detector spawn. NAV 중 detector=0, SEARCH_TAG 이후 기동 확인.
재측위 detector와 도킹 detector 동시 카메라 점유 가능성. 재측위 detector가 살아있는 상태에서 dock을 시작하면 늦은 camera busy 또는 spawn 실패로 보일 수 있다. agent가 재측위 detector 활성 중 dock start를 즉시 거부하고 reloc_detector_active 사유로 이벤트 발행.
tag9 → tag7 방향 실패와 콘솔 버튼 재시도 flakiness. tag9→tag7은 좁은 중간 지점 collision이 반복됐다. 단, worklog 기준 저배터리 영향도 아직 미배제다. 8 → 7 → 9 콘솔 경로 완주 확인. 데모는 성공 방향 우선. 배터리 충전 후 tag7→tag9, 8→7→9, 9→7 재검증이 다음 1순위.
